# ADR-002: インフラ・ホスティング構成の選定（Vercel + Render の採用）

* **ステータス**: 承認済み (Accepted)
* **日付**: 2026-08-14
* **決定者**: コウヘイ & Antigravity

---

## 1. 背景と課題

飲食店向けシフト作成AIアプリの試作品（MVP）において、**「インフラ費用完全0円」** かつ **「クライアントが異なるWi-Fiや外出先のスマホ・PCから即座にアクセスして検証できる環境」** を構築する必要がある。

### 前提要件
* **コスト**: 永続0円（クレジットカード従量課金リスクの排除）。
* **モバイルUX**: スマホ（iOS/Android）のWebブラウザで素早く開き、ストレスなく操作できること。
* **疎結合**: フロントエンドと最適化/予測API（Python）が独立してデプロイ・スケールできること。

## 4. 決定理由と経緯

**【決定】: 候補1（Vercel ＋ Render）を採用する。**

### 採用に至った決定打
1. **モバイルUIの読み込み体験（第一印象）**:
   * クライアントがスマホでURLを開いた瞬間、Vercelのエッジ配信により画面が一瞬でロードされる。商用アプリとしてのクオリティ感を損なわない。
2. **保守性と自動化**:
   * GitHubリポジトリへの `git push` でフロント・バックエンドが独立して自動ビルド＆デプロイされるため、開発運用コストがゼロ。
3. **将来の本番移行の容易さ**:
   * APIとUIがREST APIで綺麗に疎結合化されているため、将来有料クラウド（AWS / Cloud Run / Supabase等）へ移行する際もコードの変更が不要。

---

## 5. 想定されるリスクと対策

* **リスク: Render無料枠のコールドスタート（15分非活動後の初回リクエストで約50秒の待機）**
  * **対策**: フロントエンド（Vercel）側で、最適化計算リクエスト送信時に「AIエンジンを起動しています（初回のみ数十秒かかります）...」というプログレスバー/ローディング表示を設置し、ユーザーがフリーズと誤認しないUX設計を徹底する。
