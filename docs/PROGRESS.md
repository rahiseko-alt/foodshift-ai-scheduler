## 各段階で「何ができるようになるか」

### ✅ スタート地点（完了）— 法律違反と嘘の表示を直した

公開する以前の問題として、**法律違反のシフトが出る状態**でした。

- 妊娠中・産後のスタッフが深夜22時以降に入れられていた（設定が裏側で捨てられていた）
- 16歳でも生年月日を打ち間違えると深夜シフトに入れられた
- 週20時間契約の人に週50時間以上を割り当てていた
- 店長がスタッフに配る**LINEの文面にシフトが1行も入っていなかった**
- 「希望充足率100%」という数字が、実は**計算せずに決め打ち**だった

→ すべて修正済み。

### ✅ F1（完了）— 自分の店のシフトが作れる

**これができないと、公開しても初日で使うのをやめられます。**

- 期間（開始日・日数）を変えられる ← **これまで変更する画面が存在せず、永久に「2026年9月1日から14日間」しか作れなかった**
- 表示中がサンプルだと分かる ← 初めて開くと知らない15人の名前と時給が出て、自分のデータと勘違いする状態だった
- サンプルを消して自分の店をゼロから始められる ← これまで15人を1人ずつ消すしかなかった
- **調理担当が必ずシフトに入る** ← 「キッチン1人必須」と指定しても**料理を作れる人が誰もいないシフト**が出ていた
- 手で決めた配置が消えない ← 再計算のたびに消えていた
- 需要のない日に出勤させない ← 人件費の無駄が出ていた

### ✅ F2（完了）— スタッフのスマホに届く

**ここまでで「使える」に到達します。ゴールの一歩手前。**

- [x] 店長が「希望提出リンク」を作り、LINEで送れる ✅
- [x] スタッフがそのリンクを開くと**自分の名前が出る** ✅
      ← スタッフのスマホには**サンプルの15人しか出ず、自分の名前が絶対に無い**状態だった。
      名簿をURLに載せて渡す方式で解決（サーバー保存は不要のまま）
- [x] 提出した希望が、**日付がズレずに**店長に届く ✅
      ← 7日ぶんズレて取り込まれ「成功しました」と表示されていた問題を修正。
      あわせて、この不具合を検出できていなかったテスト自体の欠陥も修正
      （画面のボタンを探し損ねて**何も押さずに素通り**していた）
- [x] スタッフが店長用画面（全員の時給が見える）に入れないようにする ✅
      ← 「ホーム」ボタンが管理画面を指しており、スタッフが全員の時給を見られた

## 公開後に対応する（今回はやらない）

「まず使えること」を優先し、公開の妨げにならないものは後回しにしています。

- **休憩中の人員が「足りている」と表示される** — 8時間勤務なら45分の休憩中は
  実際には手薄だが不足として出ない。直すには時間の刻みを15分単位に作り替える
  必要があり大工事になる。**ピーク帯を1人で回す設計の店では実害が出る**ため要注意
- 複数の店舗をひとつのブラウザで管理する
- 店長とスタッフが複数の端末で同じデータを共有する（今は端末ごとに独立）
